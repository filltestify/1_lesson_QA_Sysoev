# Журнал инструментов

> Только дополняется, старые записи не редактируются. Сюда попадает всё, что вы
> добавили в проект или окружение ради этой задачи: библиотеки, CLI-утилиты,
> линтеры, MCP-серверы, плагины и скиллы агента, хуки, внешние сервисы, контейнеры.
>
> Разовый вызов уже установленного инструмента сюда не пишется — он идёт
> в таблицу инструментов внутри файла сессии.
>
> Тупиковая попытка — тоже запись: поставили, не подошло, сняли. Это как раз интересно.

## Шаблон записи

```markdown
## YYYY-MM-DD · Сессия N · <инструмент> vX.Y

- **Тип:** библиотека / CLI / MCP / плагин / скилл / хук / сервис
- **Установка:** `<точная команда>`
- **Зачем:** какую задачу решает
- **Область:** проект или глобально
- **Проверка:** чем убедились, что работает
```

Удалённый или заменённый инструмент фиксируется так же — с пометкой
**удалён** / **заменён на X** и причиной.

## 2026-08-16 · Сессия 1 · claude-in-chrome (скилл/MCP-инструмент Claude Code)

- **Тип:** скилл (браузерная автоматизация через расширение Chrome)
- **Установка:** расширение Chrome уже было установлено и подключено
  пользователем заранее; в сессии — вызов скилла `claude-in-chrome`,
  инструменты `mcp__claude-in-chrome__*` подгружены через `ToolSearch`
- **Зачем:** выполнение `test-plan.md` — клики по интерфейсу, заполнение
  формы оформления заказа, чтение консоли браузера, инъекция тестовых
  данных в `localStorage` через `javascript_tool`, проверка вёрстки на
  768px, автоматизированный DOM-ассерт для Бага 2
- **Область:** сессия (не добавляет ничего в код или зависимости
  проекта — `package.json` не менялся)
- **Проверка:** приложение открылось на `http://localhost:8765/`,
  клики/скриншоты/чтение консоли отработали на всех проверенных
  экранах (меню, корзина, оформление, подтверждение, история)
- **Известное ограничение:** `resize_window` не может сузить окно
  меньше 606px в этой среде (проверено на 768/375/320px) — не позволило
  выполнить пункт 12 тест-плана на честных 375px, см. `qa-notes.md`

## 2026-08-16 · Сессия 5 · claude-in-chrome — уточнение ограничения

Запись не редактирует запись сессии 1 выше (правило «только
дополняется»), а уточняет её по факту повторной проверки.

- **Тип:** тот же скилл, новое наблюдение о его поведении
- **Проверка:** на 4 свежесозданных вкладках один и тот же запрос
  `resize_window(375, 700)` дал 4 разных фактических результата —
  без эффекта (`innerWidth` ~1600), 606×457, 1000×657, 606×557; после
  первого успешного изменения размера конкретной вкладки повторные
  вызовы `resize_window` на ней же — молчаливый no-op (подтверждено
  явным ожиданием 2 секунды перед повторным чтением размера)
- **Вывод:** «минимум 606px» из записи сессии 1 — не фиксированный
  порог инструмента, а один из нескольких случайных исходов.
  `resize_window` в этой среде недетерминирован. Точная первопричина
  (менеджер окон ОС / состояние конкретного окна Chrome / внутренняя
  логика расширения) не установлена — сложность выхода за рамки
  прямого запроса пользователя себя не оправдывала
