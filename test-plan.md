# Тест-план — QA прототипа «Кухня у Дома» (Задание 4)

Сформирован из чек-листов по 4 зонам риска (см. `sessions/session-1.md`).
Формат пункта: вход → шаг → ожидаемый результат.
Критерии отбора и приёмки — в `SPEC.md`.
Выполнено 2026-08-16 через `claude-in-chrome` (Chrome 151, macOS) и
прямые вызовы `logic.js`/`node`. Полные скриншоты и консольные логи —
в `bug-reports.md` и `screenshots/`.

## Зона 1 — валидация формы оформления заказа

1. Ввести телефон `1234` (4 цифры), имя и адрес — валидные → нажать
   «Подтвердить заказ» → под полем «Телефон» появляется текст ошибки,
   заказ не отправляется. *(граничный)*
   **Результат: пройден.** Ошибка «Введите корректный телефон»
   показана, заказ не отправлен.
2. Ввести телефон `12345` (ровно 5 цифр — минимально допустимое),
   остальные поля валидны → нажать «Подтвердить заказ» → форма
   принимается, заказ оформляется. *(граничный)*
   **Результат: пройден.** Заказ оформлен, экран подтверждения открыт.
3. В поле «Имя» ввести `<img src=x onerror=...>`, остальные поля
   валидны → отправить заказ → на экране подтверждения зафиксировать,
   выполнился ли код или разметка отрендерилась как обычный текст.
   *(негативный, security)*
   **Результат: упал.** Тег выполнился как HTML, обработчик `onerror`
   сработал (подтверждено консолью). См. **Баг 1**.
4. Оставить поле «Адрес доставки» пустым → отправить заказ → под полем
   адреса появляется ошибка, заказ не отправляется. *(негативный)*
   **Результат: пройден.** Ошибка «Введите адрес доставки» показана,
   заказ не отправлен.

## Зона 4 — история заказов через localStorage

5. Записать в `localStorage["orders"]` заведомо не-JSON строку → открыть
   «Мои заказы» → зафиксировать фактическое поведение (падает ли экран,
   что в консоли, что видит пользователь). *(негативный)*
   **Результат: упал.** Необработанное исключение `JSON.parse`, экран
   не переключается, кнопка визуально подсвечена как активная. См.
   **Баг 2** (вариант А) — там же автоматизированный сценарий,
   падающий на этом дефекте.
6. Записать в `localStorage["orders"]` валидный JSON-массив, где один
   заказ не содержит поле `items` → открыть «Мои заказы» → зафиксировать
   фактическое поведение. *(негативный)*
   **Результат: упал.** Необработанное исключение
   `TypeError: Cannot read properties of undefined (reading 'map')`,
   тот же симптом, что и в п. 5. См. **Баг 2** (вариант Б) — один
   баг-репорт на оба варианта, общий корень проблемы.
7. Через `localStorage` выставить двум заказам одинаковый `timestamp` →
   открыть «Мои заказы» → подтвердить, что порядок отображения —
   обратный порядку добавления (детерминированная верификация поведения,
   не открытый вопрос). *(верификация)*
   **Результат: пройден (поведение подтверждено).** Заказ, добавленный
   вторым, показан первым — соответствует коду (`.slice().reverse()`),
   не дефект.

## Зона 2 — корзина

8. Добавить товар в корзину → перезагрузить страницу (F5) → открыть
   корзину → зафиксировать, сохранилось содержимое или обнулилось.
   *(граничный)*
   **Результат: зафиксировано, не дефект.** Корзина обнуляется после
   перезагрузки («Корзина 1 · 320 ₽» → «Корзина 0 · 0 ₽»). Ожидаемое
   поведение нигде не задано — см. открытый вопрос №4 в `qa-notes.md`,
   в баг не заводится.
9. Добавить товар → перейти на экран «Оформление заказа» → открыть
   панель корзины → уменьшить количество товара до удаления последней
   позиции → закрыть панель → нажать «Подтвердить заказ» → зафиксировать
   фактическое поведение. *(негативный)*
   **Результат: упал.** Молчаливый возврат в меню, введённые данные
   формы теряются без сообщения. См. **Баг 3**.

## Зона 3 — слоты доставки

10. Проверить округление времени на границе получаса с ненулевыми
    секундами. *(граничный)*
    **Изменён способ выполнения:** вместо смены системных часов (это
    системная настройка ОС, менять её не входит в область агента)
    вызвана `generateDeliverySlots(new Date(2026,7,16,18,30,5), 2)`
    напрямую через `node` — функция и так принимает `now` параметром,
    подменять системное время не требуется.
    **Результат: пройден.** Вызов с `18:30:05` вернул первым слотом
    `19:00–19:30` (округление вверх сработало); контрольный вызов с
    `18:30:00` (секунды = 0) вернул `18:30–19:00` — граница ведёт себя
    так, как задокументировано в существующих unit-тестах.

13. Проверить переход слотов доставки через полночь (переход на новые
    сутки). *(граничный, добавлен по итогам независимого аудита —
    сессия 2)* **Честно зафиксированный промах:** `SPEC.md` в разделе
    «Состояния» явно обещал проверить слоты доставки «около полуночи»,
    но исходные 12 пунктов этого плана не покрывали этот случай —
    аудит (сессия 2) указал на расхождение между обещанным в спеке и
    фактическим покрытием тест-плана.
    **Результат: пройден.** Перепроверено независимо от аудита —
    `generateDeliverySlots` вызван с `23:50:00`, `23:59:59` и
    `00:00:00` следующих суток (через `node`, без смены системных
    часов): во всех случаях слоты корректно переходят на `00:00–00:30`
    и далее, без ошибок и без day-agnostic артефактов в подписи слота.

## Вёрстка на узкой ширине (768px / 375px)

11. Открыть приложение в Chrome шириной 768px → пройти путь меню →
    корзина → оформление → подтверждение → история → нет горизонтальной
    прокрутки, элементы не наезжают друг на друга. *(граничный)*
    **Результат: пройден.** Все 5 экранов проверены на 768px — вёрстка
    корректна, прокрутки нет.
12. То же на 375px → тот же путь → то же требование. *(граничный)*
    **Результат: частично не выполнен — техническое ограничение.**
    Окно Chrome через `claude-in-chrome` физически не сужается меньше
    606px (подтверждено `window.innerWidth` при запросе 768/375/320px —
    везде 606). Испробован обходной путь через CSS `zoom` на
    `<html>` — не сработал: `matchMedia('(max-width: 420px)').matches`
    остался `false` даже при zoom 200%, то есть медиа-запрос считается
    от физического viewport, а не от CSS-зума. DevTools device toolbar
    сознательно не пробовали — риск нестабильной автоматизации ради
    одного пункта. Подробности и что реально проверено (606px живьём,
    <420px — только по коду) — в `qa-notes.md`.
